# 本地一键切换实盘

## 首次配置

在本机 `C:\Users\11617\.okx\config.toml` 的原有内容后增加独立 profile，填入实盘 API 凭证。不要覆盖已有 demo profile，不要把真实密钥提交到仓库或聊天。

```toml
[profiles.live]
demo = false
api_key = ""
secret_key = ""
passphrase = ""
```

默认读取 `live` profile；可通过 `OKX_LIVE_PROFILE` 指定其他名称，通过 `OKX_CONFIG_TOML` 指定凭证文件。未填凭证或环境标志不匹配时切换失败，不会自动降级到另一个账户。创建 API 时只授予读取和交易权限，绑定本机出口 IP；不需要提币权限。建议使用独立子账户，避免与人工交易或其他机器人共用仓位。

OKX 账户需要设置为单向持仓模式。程序只验证账户模式，不会自动修改。使用的 API 域名需适用于你的账户注册区域；本实现使用 ccxt OKX 默认域名，不自动猜测区域。

## 启动与切换

1. 关闭旧版平台进程，然后双击 `start-platform.bat`。保持该窗口和电脑运行。
2. 打开「自动」标签，查看「交易环境」面板。实盘基础配置是 `config/pilot.yaml` 的 ETH、BTC 与 EMA 交叉策略；自动学习验证通过后，可使用来源于模拟盘的趋势或波段规则。界面会显示实际策略和版本，资金、杠杆与持仓仍独立。
3. 点击「切换实盘并启动（真实下单）」。这一次点击授权持续自动交易，不会在每一笔订单前再次询问。
4. 程序验证实盘 API、账户 UID、净持仓模式、余额、账本、未成交委托、止损保护和最小下单量，通过后启动本机后台线程。面板显示 UID、USDT 权益、运行状态与本程序账本持仓。

默认固定止损 1.5%，最多 3 倍杠杆，按权益 0.25% 的单笔预算反推名义金额，包含估计 20 bps 的往返成本预留。组合预算 0.75%，同方向合计 0.5%，名义金额总上限 3000 USDT。账户回撤 5% 或连亏三笔触发熔断。费用预留不是真实费率或亏损保证；止损可能发生跳空、滑点或交易所拒单。预算不足以满足合约最小下单量时不会放大仓位。

实盘首次成功切换后绑定账户 UID，使用独立 `data/live-state.yaml`。已有未知仓位、普通挂单、未知策略单、保护单缺失或仓位数量不符会阻止执行；不会自动接管、撤销或平掉未知仓位。18789 本机端口用于避免两个平台实例同时运行实盘执行器。模拟自动交易可与实盘并行，账本彼此独立。

## 模拟盘自动验证并更新实盘

后台每十分钟检查一次，并补齐本地 ETH/BTC 最近 24 天的行情。它读取当前模拟策略配置作为候选来源，保留其均线、趋势/波段入场、移动止盈、冷却和趋势入场次数规则；当前参数搜索仅比较 ADX 原值、加 5、加 10（候选加值上限 40）。这属于有限参数搜索与影子回放验证，不是训练神经网络，也不会凭几笔模拟盈利无限扩展交易权限。

先用过去 14 天选一个扣成本后盈利且至少 30 笔的候选，再冻结参数、基准版本和成本/风控模型。候选冻结之后的未来 7 天才用于验证，不能拿冻结前的行情冒充未来验证。候选与基准都用固定止损和相同成本回放；验证标准是总交易至少 30 笔、每个标的至少 10 笔且净盈利、收益因子至少 1.2、平均名义本金净收益比基准高至少 20 bps、单标的名义本金最大回撤不高于 5% 且不明显劣于基准，并通过 1.5 倍成本压力测试。这里的收益和回撤是等名义本金回放指标，不是实际组合账户收益率。所有门槛都只是工程筛选条件，不证明未来收益。

缺失 K 线、过期行情、样本不足、配置变化或验证失败时保留旧版本。通过后记录新旧版本及验证指标，实盘只有在交易所已对账、全部持仓已平、没有待核对订单时才自动换版；有持仓继续使用账本固定的原策略。重启也沿用该持仓版本。更新不会提高资金风险、杠杆、修改凭证或自动增加交易标的，亦不会自动解除熔断或恢复暂停的新开仓。

验证状态和版本记录在本地数据库 `strategy_learning_v1` 元数据中；当前实盘版本保存在独立账本 `strategy_release`，保留上一版供核对。当前保留最近 20 次验证记录。学习不会把旧的混合策略订单直接算成某个新版本的成功样本；主要证据是冻结参数的影子回放。模拟与实盘仍有盘口、资金费、延迟、指标初始化窗口和组合资金约束差异，影子验证不替代真实成交核对。

## 暂停、退出与恢复

- 「暂停新开仓」只禁止新增仓位，仍允许策略退出和风控处理已有仓位。它不能撤回已经发送的订单请求。
- 「切回模拟」要求交易所空仓、账本结算完成且没有待核对请求。切回后模拟自动交易保持关闭，可另行启动。
- 重启后重新验证实盘账户，恢复持仓检查，但保持新开仓暂停；需要再次点击启动。启动前所有持仓应已有交易所托管止损。
- 关闭本机或程序后，本地策略、扫描、反转退出和账户熔断不再运行；已被交易所接受的止损单由交易所处理。关闭窗口不是平仓操作。
- 需要手动平仓时在 OKX 操作，程序会读取成交与费用核对。不要同时人工加仓或运行另一套交易机器人。

订单请求发出前会把 `client_id` 记入独立账本。若请求超时、成交不完整或落盘失败，执行器停止新增交易并保留账本。先到 OKX 按订单号或客户端订单号核对成交、持仓和保护单，再修复账本；不要直接删除账本或清除 `pending_entry` 重启。

网页其余账户、订单历史和统计面板仍是本地模拟数据，实盘以「交易环境」面板与 OKX 为准。模拟手动交易、重置账户和自动交易修改接口在实盘模式被禁用。接口只支持本机同源控制，不要把后端暴露到公网。

## 验证范围

自动化验证使用模拟交易所对象，覆盖凭证环境隔离、账户变更拒绝、未知仓位与策略单拒绝、保护单缺失、暂停、重启、跨站请求、订单超时意图持久化及回归测试；没有使用真实凭证，也没有执行实盘下单验证。交易所托管止损遵循 [OKX API 文档](https://www.okx.com/docs-v5/zh/)；上线前仍需小额核对完整成交和止损流程。
