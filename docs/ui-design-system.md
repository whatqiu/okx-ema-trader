# OKX EMA Trader — 界面设计规范

版本 2.0 · 2026-10-06 · 像素君

---

## 一、这次重设计要解决什么

先看旧版的问题。这些都是读代码读出来的，不是印象：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 基准字号 13px | Windows 100% 缩放下已开始糊，而这是需要长时间盯盘的界面 |
| 2 | 右栏 300px 塞了 5 个功能（手动交易/自动交易/回测/历史/持仓） | 每个任务都被挤压，最重要的下单按钮和回测表单共用一条竖列 |
| 3 | 信号流的 `reason` 字段单行截断 | 策略判断依据（"为什么给这个信号"）永远看不到 |
| 4 | 强平价藏在第二行灰色 11px 字里 | 它决定用户会不会被强平，却被当成次要信息 |
| 5 | 权益曲线是 100×28 的 polyline | 只能表达"涨了还是跌了"，看不出回撤深度 |
| 6 | 瞬时消息用顶部横幅 | 一条 toast 就把图表往下挤，页面位置跳变 |
| 7 | 6 处交互按钮 min-height 小于 32px | 鼠标难以稳定命中 |
| 8 | 自动交易参数初值硬编码 100/5/3，而后端实跑 3000/20/5 | **用户看到的是从未生效过的数字**，改一个参数可能把仓位规模改掉 30 倍 |

第 8 条是真 bug，不是观感问题——已在本次重写中修掉（见第五节）。

**核心矛盾**：旧版把"观察动作"和"交易动作"放在同一列。盯盘是持续的、浏览式的，下单是瞬时的、需要全部注意力的工作。两者混在一起，两边都做不好。

**解法**：右侧改为标签页，每个任务独占完整空间；观察类信息（账户、信号、行情）留在左栏常驻。

## 二、设计基础

### 色彩策略

**涨跌色采用绿涨红跌**，与 OKX / Binance 一致。这不是随意的选择——用户在交易所看到的颜色必须和这里相同，否则会误判盈亏方向。

如需 A 股红涨绿跌，只覆写 4 个变量，组件代码不动：

```css
:root { --c-up: #d32f42; --c-down: #078455; }
```

**强色只给涨跌**：琥珀（主色）用于交互，警示黄用于警告，红绿用于盈亏。其余全部降饱和——否则界面会变成圣诞树。

### 令牌层

全部令牌集中在 `design/tokens.css`，组件**不允许**硬编码色值/字号/间距。20+ 组件共用一套变量，改主题只动一个文件。

```
表面层级（靠明度差建立层次，不靠边框堆叠）
  --bg-root      #0a0d12   页面最底
  --bg-sunken    #070910   凹陷：图表底、输入框
  --bg-base      #11151d   常规面板
  --bg-raised    #171c26   浮起：卡片、悬浮
  --bg-overlay   #1d2330   最高层：弹窗

描边只两级（第三级会让密集面板变成筛子）
  --line-soft / --line / --line-strong

文本四级
  --tx-primary    #e9edf4   15.57:1  AAA
  --tx-secondary  #a8b2c1    8.53:1  AAA
  --tx-tertiary   #7b8697    4.96:1  AA
  --tx-disabled   #5a6474   仅禁用态，不承载信息
```

### 排版

基准 **14px**（原 13px）。可读性优先于"一屏塞更多"。

```
字号  10 / 11 / 12 / 14 / 15 / 18 / 22 / 28 / 34
字重  400 / 500 / 650
行高  1.25 紧凑 · 1.4 适中 · 1.55 正常
```

**所有数字强制 `tabular-nums` + 等宽字体**。非等宽数字每次刷新宽度都会跳变，用户会以为值变了——这是盯盘界面最容易被投诉的细节。

### 间距与圆角

4px 基准：`4 8 12 16 20 24 32 40`

圆角偏小（3/5/8px）。大圆角在密集数据界面会显得玩具化。

## 三、布局重构

```
旧:  250px │ 1fr │ 300px          右栏塞 5 个功能
新:  300px │ 1fr │ 380px          右栏按任务拆标签页
```

整页固定视口高，列内各自滚动。**不允许整页滚动**——数据增长导致图表位移是不可接受的。

### 响应式断点

| 断点 | 布局 |
|---|---|
| > 1440px | 300 / 1fr / 380 |
| 1180–1440px | 272 / 1fr / 344 |
| 960–1180px | 244 / 1fr / 320，参数区转 2 列 |
| < 960px | 单列纵向堆叠，图表置顶，**触控目标升到 44px** |
| < 720px | 顶栏换行，参数区转单列 |

移动端不靠缩小字号来塞内容——靠放大触控目标和重排。

## 四、组件规范

### 高度与密度

桌面端 min-height 32px，移动端 44px（WCAG 2.5.5）。

### 焦点样式

统一在令牌层定义：

```css
:focus-visible { outline: 2px solid var(--c-info); outline-offset: 2px; }
```

这不是装饰。在交易界面里"焦点在哪"直接决定"会不会下错单"。

### 状态三重编码

所有状态用**颜色 + 形状/文字 + 位置**，不靠颜色单独承载：

| 状态 | 颜色 | 文字 | 附加 |
|---|---|---|---|
| 已连接 | 绿 | "已连接" | 实心圆点，静止 |
| 断网 | 红 | "断网 46秒" | 实心圆点 + 全宽横幅 + 持续时长 |
| 风控熔断 | 红 | "风控熔断" | 全宽横幅 + 解除按钮 |
| 连亏中 | 黄 | "连亏2" | 徽标（注意：这是**警示**不是**失败**） |

原因：约 8% 的男性有色觉障碍，而"已连接/断网"判断错误的代价是用户误以为行情正常。

呼吸动画**只用于"正在进行中"**（如连接中）。已连接/断网不闪——闪烁会诱发焦虑且无信息量。

### 减弱动效

```css
@media (prefers-reduced-motion: reduce) { /* 全部动画归零 */ }
```

前庭功能障碍用户会因视差/闪烁眩晕，这是硬要求不是可选项。

### 空状态

每个空白区域都回答两件事：**为什么空** + **下一步做什么**。

> 暂无信号记录
> 自动交易每根 5m 收盘评估一次，出现方向判断才会写入这里

## 五、本次修掉的真实缺陷

这些不是样式问题，是会导致错误决策的问题。

### 1. 强平缓冲公式符号写反（我在设计过程中写错的，已修正）

最初写成统一公式，导致真实持仓 MU（20x 空单，现价 1059.91，强平价 1121.69）显示 **"距强平 -5.8%"**。

推导过程纠正为：

```
多头爆仓要跌到强平价 → 还要跌 (现价 - 强平价)/现价
空头爆仓要涨到强平价 → 还要涨 (强平价 - 现价)/现价
```

六个场景已逐一验算（健康多头 5x、临界 20x、多头被穿越、健康空头 3x、真实 MU 空单、缺现价）全部正确。

文案也带上方向（"再跌即强平" / "再涨即强平"），用户不用自己判断方向。

**越界状态**：现价越过强平价时显示"已越过强平价" + 斜纹填充条。纯红条会和"缓冲不足"混淆，而后者只是快爆仓，前者是状态不一致需要人工介入——两者必须能区分。

### 2. 交易台与后端的强平价公式不一致

交易台多减了维持保证金系数（0.005），后端 `paper.py:liquidation_price()` 没减。结果同一个数字在两个界面显示不同值。

已统一到后端口径。**宁可两边都用粗略公式，也不要各自"更精确"却互相矛盾。**

### 3. 手续费只报单边

后端 `TAKER_FEE_BPS = 5.0`，开仓收一次、平仓再收一次。前端只显示单边，用户会以为实际成本是显示值的一半。已改为展示双边总额。

### 4. 自动交易参数初值与实际配置脱节（严重）

见第一节第 8 条。已改为从 `/api/autotrade` 同步。

**同类风险的处理方式**：输入框初值一律视为"显示占位"，真实配置以服务端返回为准。

### 5. 风控平仓提示重复刷屏

`loadStatus()` 每 4s 轮询，同一笔风控平仓会反复弹 toast。已加签名去重。

### 6. canvas 硬编码色值导致主题切换失效

`KlineChart` 有 8 处硬编码色值。canvas 的 `fillStyle` 不接受 CSS 变量，必须运行时读取计算样式——并用 `MutationObserver` 监听 `data-theme` 变化重绘，否则切到浅色主题会看到一块黑底图表。

`onBeforeUnmount` 必须断开 observer：这个组件在标签页切换时反复挂载卸载，泄漏的观察器会累积。

## 六、无障碍实测结果

不是"声称符合 WCAG AA"，是实测值。

### 深色主题（面板底 `#11151d`）

| 用途 | 色值 | 对比度 | 等级 |
|---|---|---|---|
| 主要文本 | `#e9edf4` | 15.57:1 | AAA |
| 次要文本 | `#a8b2c1` | 8.53:1 | AAA |
| 三级文本 | `#7b8697` | 4.96:1 | AA |
| 涨 / 盈利 | `#1fc98b` | 8.52:1 | AAA |
| 跌 / 亏损 | `#f2495c` | 5.12:1 | AA |
| 警示 | `#e8a33d` | 8.48:1 | AAA |
| 主色 | `#f0b90b` | 10.14:1 | AAA |

### 浅色主题（面板底 `#ffffff`）

| 用途 | 色值 | 对比度 | 等级 |
|---|---|---|---|
| 主要文本 | `#0b1220` | 18.72:1 | AAA |
| 次要文本 | `#4a5567` | 7.54:1 | AAA |
| 三级文本 | `#667080` | 5.01:1 | AA |
| 涨 / 盈利 | `#078455` | 4.73:1 | AA |
| 跌 / 亏损 | `#d32f42` | 4.94:1 | AA |
| 警示 | `#96600a` | 5.28:1 | AA |
| 主色 | `#8a6508` | 5.32:1 | AA |

### 交互元素

| 元素 | 对比度 |
|---|---|
| 琥珀按钮文字 `#0a0d12` on `#f0b90b` | 10.79:1 |
| 涨绿按钮文字 `#0a0d12` on `#1fc98b` | 9.07:1 |

### 一处有意保留的权衡

凹陷底 `--bg-sunken(#f2f4f7)` 上，涨跌色为 4.29 / 4.48:1，未达正文 4.5。

**这是有意的**：那里的涨跌色只用于 22px 以上的成交参考价与强平价，WCAG 对 ≥18.66px 的文本只要求 3:1。若压到 4.5，白底上的数字会暗到不自然。若提亮凹陷底，对比度反而更低（底越浅越接近色相）。已写入代码注释，避免被误判为缺陷后"修复"。
